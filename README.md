# シングルプレイ共有スコアサーバー

LAN内のUnityからHTTPでランキング取得・登録を行い、ホストPCのSQLiteへ永続保存します。スマホ操作用のシグナリングサーバーとは別に動きます。Node.js 24以上を使用し、追加npmパッケージ・PostgreSQLは不要です。

## 起動

Node.js 24以上を用意し、このリポジトリを取得して起動します。追加npmパッケージのインストールは不要です。

```sh
git clone https://github.com/nyaran2910/KosenChanbaraScoreServer.git
cd KosenChanbaraScoreServer
npm start
```

同じLAN内のPCのうち1台で起動すれば、各Unityが自動でサーバーを見つけます。IP固定や各UnityへのIP入力は不要です。Unityを先に起動していても、次のランキング取得時に検出します。

総合リポジトリの `apps/score-server` として取得している場合は、総合リポジトリのルートで `just score-server` でも起動できます。HTTPは `0.0.0.0:3080`、探索はUDP42044で待ち受けます。終了はCtrl+Cです。サーバー用PCはプレイ中、起動した状態を保ちます。インターネット接続は不要です。

## 自動検出

Unityを普通に起動すれば自動で接続します。接続コマンドやIP設定はありません。以前の接続先設定が残っていても参照しません。

- Unityは約1秒間、UDP42044へブロードキャストし、応答元IPと通知されたHTTPポートを使います。同じPC向けにループバックへも探索します。
- 使用中のIPv4インターフェースごとのブロードキャスト先へも送信します。Wi-Fiと有線LANがある場合も、同じDBの応答は1台分にまとめます。
- 接続先は正常に応答する間キャッシュし、HTTP接続に失敗したら破棄して再探索します。DHCPでIPが変わっても、次の通信時に探索し直します。
- 複数の異なるスコアサーバーが見つかった場合は1台だけ起動するよう表示し、勝手に保存先を選びません。
- 名前入力と送信の再試行は、順位確認を行ったDBの識別子に紐づけます。別の空のサーバーへ同じ記録を再送しません。DBの識別子はSQLite内に保存するので、再起動やDBファイルの移動でも維持されます。

ファイアウォールでLANからのTCP3080とUDP42044を許可します。同じWi-Fiでも端末間通信やブロードキャストが禁止されたネットワークでは接続できません。ブラウザで `http://サーバーのIP:3080/health` を開き、`ok: true` と `serverId` を含むJSONが返ればHTTPに到達しています。サービスは信頼するLAN内で使う想定です。

## ゲーム内の動き

- シングルのキャラ選択で、選択UIを左、難易度ごとの上位10件を右に表示します。表示中は10秒ごとに更新します。
- イージーとノーマルは別ランキングです。撃破数の降順、同点は登録が早い順です。空き枠があれば0人の記録も登録できます。
- 死亡の2秒後に結果画面と順位確認を開始します。100人クリアも対象です。10位以内なら名前欄が開きます。
- 名前はキーボードで入力し、「登録する」をクリックするか、コントローラのガードで登録します。名前入力中のWASD・Shift・R・数字キー・Tは文字入力に使います。スキップまたはEscで登録を省略できます。
- 名前は1〜12文字です。サーバーで全角英数字などを正規化し、前後の空白を除きます。各プレイが1件の記録になり、同じ名前の複数記録も残せます。
- 名前入力中に順位が変わった場合は登録時にも10位以内か再判定します。圏外ならその旨を表示します。
- 通信失敗時は再試行できます。同じプレイIDの送信は二重登録されません。送信結果が不明な場合の再試行では最初に送った名前を維持します。登録を完了せず終了した記録の自動送信は行いません。
- チュートリアル・対戦・フリー、および数字キーの区間移動を使ったプレイは登録対象外です。

## 保存と設定

既定の保存先はこのディレクトリの `data/scores.sqlite` です。サーバー再起動でも記録は残ります。バックアップやサーバーPCの変更時は、サーバーを停止してからDBファイルをコピーします。自動検出は接続先を探す機能で、異なるPCのDBを自動同期する機能はありません。

| 環境変数 | 初期値 | 用途 |
| --- | --- | --- |
| `SCORE_HOST` | `0.0.0.0` | サーバーの待受アドレス |
| `SCORE_PORT` | `3080` | サーバーの待受ポート |
| `SCORE_DISCOVERY_PORT` | `42044` | UDP探索の待受ポート。変更時はUnity側の `KOSEN_SCORE_DISCOVERY_PORT` も合わせる |
| `SCORE_DB_PATH` | `data/scores.sqlite` | SQLiteファイルの保存先 |

## Dockerで動かす場合

このディレクトリで次を実行します。

```sh
docker compose up -d --build
docker compose logs -f
```

TCP3080とUDP42044を公開します。Docker Desktopなどの仮想ネットワークによってはLANのブロードキャストがコンテナへ届かないため、Dockerで探索できない場合はPC上で `just score-server` を実行してください。停止は `docker compose down` です。DBは名前付きvolume `score-data` に残ります。データを維持するときは `down -v` を使わないでください。

## API

| メソッド | パス | 動作 |
| --- | --- | --- |
| GET | `/health` | 稼働確認 |
| GET | `/api/scores?difficulty=normal` | 上位10件取得 |
| GET | `/api/scores/qualification?difficulty=normal&defeated=88` | 仮の順位・登録可否取得 |
| POST | `/api/scores` | 登録時の順位を確認し、10位以内なら保存 |

POSTは `Content-Type: application/json` で次を送ります。`runId` はプレイごとに生成したUUID v4を再試行時も維持します。

```json
{
  "runId": "c68d72d0-512e-4efc-a055-04fe0dd75782",
  "name": "こせん",
  "difficulty": "normal",
  "defeated": 88,
  "serverId": "順位確認の応答に含まれるserverId"
}
```

新規登録は201、同一内容の再送は200です。登録時に圏外なら409と `code: "NOT_QUALIFIED"`、同じIDで内容を変更した場合は409と `code: "RUN_CONFLICT"` を返します。順位判定と挿入は1つのトランザクションで行います。全てのランキング応答に `difficulty` と `entries`（順位・名前・撃破数など）を含めます。

全てのAPI応答にDB固有の `serverId` を含めます。接続先を確認する `X-Kosen-Score-Server` ヘッダー、またはPOSTの `serverId` がこのDBと異なる場合は、保存せず409と `code: "SERVER_CHANGED"` を返します。

探索の要求は `{"type":"kosen.score.discover","version":1,"nonce":"32桁の小文字16進数"}` です。サーバーは送信元へ `{"type":"kosen.score.offer","version":1,"nonce":"要求と同じ値","serverId":"DBのUUID","port":3080}` を返します。Unityは応答内の任意のURLを使わず、UDP応答元のIPを使います。

## 確認

```sh
npm test
```

HTTP経由の順位・同点・難易度分離・同時登録・二重送信・不正入力・再起動後の保存、UDPのブロードキャスト・要求検証を確認します。Unityでは `Tools → Kojo Checks → Run Scoreboard Discovery` が探索・登録・結果画面の関連テストを実行します。`Run Scoreboard Play` は一般のメニュー操作も含めた確認と画面キャプチャ（`/tmp/sf-score-preview`）を実行します。自動探索・キャッシュ・後からの起動・接続先変更時の再探索・複数DB検出・別DBへの再送防止を含みます。
